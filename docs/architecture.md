# Архитектура и ограничения

## Модули

| Crate | Назначение |
| --- | --- |
| `gost-sign-rust` | Подпись, проверка пары ключ–сертификат, объект SigningIdentity и единый CLI `gost-sign`. |
| `gost-sign-pfx` | Стандартный PKCS#12 через `p12-keystore`, шифрование и проверка MAC. |
| `gost-sign-export` | Чтение шестифайлового контейнера, расшифровка ключа, сертификаты, опциональный PC/SC. |
| `gost-sign-cms` | Подготовка/сборка detached CAdES-BES и строгая математическая проверка. |
| `gost-sign-core` | Streebog-256/512, X.509 DER и выбор поддерживаемых параметров. |
| `gost-sign-experimental` | Арифметика проверки открытых данных, не предназначена для секретных скаляров. |
| `gost-sign-php` | Тонкий PHP API; системный PHP SDK нужен при сборке. |
| `gost-sign-openssl` | Необязательный legacy-импорт и независимые проверки совместимости. |

Основной путь: контейнер → проверка MAC/пароля → расшифровка PKCS#8 в памяти → вычисление открытого ключа и сравнение с сертификатом → PFX с новым паролем → подпись на Rust. Вызовов внешних криптографических команд в этом пути нет.

## Криптография

- Хеширование/ASN.1: RustCrypto. Модульная арифметика: `crypto-bigint 0.7.5`.
- Секретное умножение точки — локальный адаптер координат Якоби: 256 шагов, условный выбор через `subtle`, обработка исключительных точек. Формулы [EFD](https://www.hyperelliptic.org/EFD/g1p/auto-shortw-jacobian.html).
- Одноразовый скаляр подписи берётся из генератора ОС с отбрасыванием значений вне диапазона. Это не детерминированная тестовая подпись.
- Кривые: TC26-256-A; CryptoPro-A, XchA и TC26-B. Подпись ГОСТ-512, остальные кривые и аппаратное подписание Рутокен ЭЦП не реализованы.
- ГОСТ-подпись: `s_BE || r_BE`; открытый ключ: `x_LE || y_LE`; хеш интерпретируется как little-endian целое.
- CMS: DER, один подписант и сертификат, detached id-data, Streebog-256, issuer/serial, contentType/messageDigest/SigningCertificateV2. Проверка допускает signingTime, но не считает его доверенной меткой времени. Цепочки, CRL, unsigned attributes и другие профили не поддерживаются.

Фиксированный порядок вычислений в исходном коде не означает доказанное постоянное время машинного кода. Независимого криптографического аудита нет. Проверка математической корректности не устанавливает доверие сертификату, срок действия, отзыв или полномочия подписанта.

## Хранение

Стандартный PFX/P12: PBES2, AES-256-CBC, PBKDF2/SHA-256, SHA-256 MAC; 100 000 итераций. Требуется новый непустой UTF-8 пароль без NUL, максимум 1024 байта. При импорте обязателен MAC, поддерживается один ключ и один сертификат с согласованным localKeyId. Полную проверку соответствия ключа выполняет SigningIdentity.

Старый PFX КриптоПро с OID `.80` остаётся в необязательном OpenSSL backend. Универсальная совместимость экспортируемого PFX со всеми ГОСТ-продуктами не заявляется.

Контейнер КриптоПро: профиль из `masks.key`, `primary.key`, `header.key`, `masks2.key`, `primary2.key`, `name.key`; ASCII-пароли источника. Поддержка резервного ключа, всех версий хранения и реестра Windows не заявляется. Декодирование основано на открытых MIT-источниках [cpfx_ts](https://github.com/li0ard/cpfx_ts) и [gost](https://github.com/li0ard/gost); уведомления сохранены в `licenses/`.

Основные буферы ключа/PKCS#8/nonce очищаются через Zeroizing, но все копии промежуточных вычислений, PHP-строки и память зависимостей не гарантированно обнуляются. Блочный шифр используемой зависимости применяет табличные обращения. CLI пишет результат атомарно через временный файл, запрещает перезапись; на Unix файл создаётся с правами 0600, на Windows действуют ACL папки. Пароль не хранится в PFX открыто; исходный PIN не переносится.

## Проверки

Публичные тесты используют стандартные векторы и заведомо публичный скаляр d=1. Интеграция с CSP использует одноразовый офлайн-контейнер. Личные ключи для CI не нужны.

`scripts/generate-public-cms-fixture.py` воспроизводит публичную тестовую фикстуру независимой арифметикой. Он не нужен для сборки и работы продукта.
