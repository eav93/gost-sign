# Экспорт ключа и сертификата

Результат полного экспорта — стандартный `.pfx`, содержащий закрытый ключ и сертификат, защищённые новым паролем. Экспорт `.cer` содержит только открытый сертификат и не позволяет подписывать документы.

## Из локального контейнера КриптоПро

Нужна папка контейнера `.000` с файлами:

```text
masks.key
primary.key
header.key
masks2.key
primary2.key
name.key
```

Это копия файлов программного контейнера, а не сертификат `.cer`/`.p7b` и не старый экспорт `.pfx`. Поиск Windows также проверяет доступные ветки реестра КриптоПро. Экспорт поддержан для записей REG_BINARY с теми же шестью именами; другие профили реестра отклоняются.

1. Запустите `gost-sign` (`gost-sign.exe` на Windows).
2. Выберите **5 — Выбрать или сменить контейнер**.
3. Выберите **1 — Найти контейнеры КриптоПро на компьютере** (Enter). Программа проверит штатные хранилища; если контейнер скопирован в другое место, используйте поиск по указанной папке.
4. В списке показаны все найденные контейнеры и открытые сертификаты: владелец, организация/ИП, ОГРН/ОГРНИП при наличии, срок действия и источник. Введите номер нужного контейнера.
5. Выбор сохраняется в текущем сеансе и отображается над главным меню. Для замены снова выберите пункт **5**. Отмена выбора оставляет предыдущий контейнер.
6. Выберите **3 — Экспорт выбранного контейнера в PFX**. Проверьте карточку и нажмите Enter; `:назад` возвращает в меню до запроса пароля/PIN.
7. Если контейнер защищён, введите исходный пароль. При нескольких встроенных сертификатах выберите нужный; программа проверит его соответствие основному закрытому ключу.
8. Укажите имя PFX и новый непустой пароль дважды.

Исходные файлы остаются без изменений. Поддержаны ASCII-пароли исходного контейнера; новый пароль PFX допускает UTF-8. Файл назначения не должен существовать.

## С Рутокен Lite 1010

1. Подключите токен и закройте приложения, удерживающие карту.
2. В главном меню выберите **5 — Выбрать или сменить контейнер**, затем **2 — Найти контейнеры на Рутокен Lite**.
3. Программа проверит подключённые считыватели и каталоги `0a00–0aff`. Поиск читает только заголовки, не отправляет PIN и показывает ход выполнения. Через удалённый PC/SC поиск может занять больше времени.
4. Выберите контейнер по сертификату и источнику. Если открытый заголовок защищён, вместо данных сертификата показано «требуется авторизация». Такой контейнер можно выбрать для полного экспорта.
5. Выберите **3**, проверьте карточку и подтвердите Enter. PIN запрашивается только если выбранная карта отказывает в чтении без авторизации. Выполняется одна попытка; пустой ввод отменяет действие. Отдельный пароль контейнера запрашивается только при наличии его защиты.
6. После проверки пары ключ–сертификат задайте имя PFX и новый пароль дважды.

PIN не устанавливается и не изменяется. Программа не угадывает стандартные PIN. Отказ при неверном PIN завершает действие; повторный вход возможен только после нового действия пользователя. После успешной авторизации права сбрасываются по завершении чтения.

Поддержан только указанный профиль Lite 1010; Рутокен ЭЦП и аппаратные неизвлекаемые ключи не поддерживаются. Работа с физическим устройством требует отдельной проверки; текущие тесты проверяют протокол на имитации карты.

## После переноса

Для подписи выберите пункт **1**, укажите PFX, его новый пароль и документ. Токен, туннель, исходный PIN и установка КриптоПро для этого не нужны. Убедитесь, что подпись проходит проверку пунктом **2**, прежде чем менять исходную конфигурацию хранения ключа.

## Только сертификат

Для выбранного контейнера используйте **6 — Экспорт сертификата выбранного контейнера**. Для произвольного PFX или файла используйте пункт **4**. Для PFX нужен его пароль. Для токена читается только заголовок, PIN не отправляется. Если чтение запрещено картой, операция завершается ошибкой. Выходной файл — X.509 DER `.cer`.

## Пример Rust: локальный контейнер

Запускаемый пример находится в `crates/gost-sign-rust/examples/export_container.rs`:

```sh
cargo run --release -p gost-sign-rust --features cli --example export_container -- /path/container.000 /path/identity.pfx
```

Пароли вводятся скрыто. Основные вызовы для включения в приложение:

```rust,ignore
use gost_sign_export::container::Container;
use gost_sign_rust::SigningIdentity;

let container = Container::from_directory(container_path)?;
// source_password запрашивается у пользователя только если
// container.source_password_required()? вернул true; иначе используется "".
let pkcs8 = container.primary_pkcs8(source_password)?;
let certificates = container.certificates()?;
if certificates.len() != 1 {
    return Err("Требуется один встроенный сертификат".into());
}
let identity = SigningIdentity::import_pkcs8(&certificates[0], &pkcs8)?;
let pfx = identity.export_pkcs12(new_password)?;
// Сохраните pfx с запретом перезаписи и ограниченными правами доступа.
```

## Пример Rust: Рутокен

Включите feature `pcsc` у `gost-sign-export`. В приложении выберите считыватель и передайте callback скрытого ввода PIN:

```rust,ignore
use zeroize::Zeroizing;

let readers = gost_sign_export::token::readers()?;
let reader = readers.first().ok_or("Считыватель не найден")?;
let container = gost_sign_export::token::container_with_pin(reader, 0x0a00, || {
    let pin = Zeroizing::new(rpassword::prompt_password("PIN пользователя: ")?);
    Ok(Zeroizing::new(pin.as_bytes().to_vec()))
})?;
// Затем source_password_required → primary_pkcs8 → certificates →
// SigningIdentity::import_pkcs8 → export_pkcs12, как в примере выше.
```

Callback вызывается только после отказа чтения из-за отсутствия авторизации; вызов не означает обязательный ввод PIN для каждой карты.

## Примеры подписи

Rust, со скрытым вводом пароля:

```sh
cargo run --release -p gost-sign-rust --features cli --example sign_pfx -- identity.pfx invoice.pdf invoice.pdf.p7s
```

PHP, после подключения расширения:

```sh
php examples/php/sign.php identity.pfx invoice.pdf invoice.pdf.p7s
```

PHP-пример получает пароль из `GOST_PFX_PASSWORD`, установленного окружением приложения. Не помещайте рабочий пароль в историю shell. В серверном приложении вместо переменной окружения можно использовать менеджер секретов. Сам CLI `gost-sign` пароли из env не читает.
